## Existing architecture and preservation boundary

The working tree was clean. The application is a dependency-free browser-local mockup, not a deployed REST application. Its UI is `src/app.mjs`/`src/ui.mjs`; rules are in `src/domain.mjs`; `src/mock-auth.mjs` and `src/mock-api.mjs` separate identity and business responsibilities; `src/store.mjs` provides IndexedDB; `src/records.mjs`/`src/sync.mjs` implement the single offline outbox. `src/media.mjs`, `service-worker.js`, and `public/manifest.webmanifest` support media and the scoped PWA. `scripts/serve.mjs` is a static loopback server, with API paths intentionally absent. No Workers, SQL migrations, service bindings, remote database, credentials or deployment pipelines exist.

Applicable instructions: `sitelog/AGENTS.md`; no ancestor/root or nested AGENTS files were found. Its local-only scope and preservation rules remain applicable. All work stays under `sitelog/`. Existing UI, IDs, records, blobs, assignments and queues must be preserved; no reseed/reset on upgrade. Actual server-side identity, permissions and concurrency cannot be claimed for a client-only mock. No production/deployment changes are part of this stage.

## Stage 1 implementation plan and completion gates

1. Add indexed `workSchedules` without renaming the database or touching existing records. Copy only explicit legacy personal defaults into a clearly labelled migration record; do not fabricate working-day defaults for users with no configuration. Preserve timed and hours-only history. Record migration version/policy and recovery instructions.
2. Add pure effective-schedule validation/selection and `TimeSuggestion` logic: all-job interval subtraction, next/earlier choices, remaining unpaid break, legacy review and non-working/fully-covered cases. Keep minute/DST/overnight rules in the existing domain boundary.
3. Add an admin-managed effective-dated weekly schedule editor with weekday copy shortcut, audited revisions and expected-version checks. Workers can read their own schedule and keep manual control of actual time. Preserve old personal settings without letting them silently override central configuration.
4. Put identity, authorisation, locked-entry checks, overlap/version checks, history/idempotency and acceptance inside one IndexedDB transaction at the existing mock service boundary. Add role-specific workspace DTOs and preserve the single queue. Overlaps return recoverable conflicts and keep local work editable.
5. Extend the existing time dialog with effective-date/worker context, clear suggestions and explicit gap choices. Preserve saved edits/drafts, avoid silent replacement on context changes, use sticky mobile actions and collapsed optional detail. Improve existing nearby-job UI without adding GPS storage or external maps.
6. Run baseline and new unit/browser tests, including a disposable v1 database upgrade with media/outbox preservation; concurrent submissions without Web Locks; offline correction/restart; locked permissions; projection exclusion; GPS denial/poor accuracy/adjacent sites and mobile layout. Document actual-phone and server limitations.

## Decisions and blockers

Routine choice: keep the established browser-local architecture and test the existing mock API boundary rather than inventing a backend or adding Cloudflare now. This follows AGENTS.md and the user's prior local-only instruction. Production server authentication, CSRF/RPC and true cross-device enforcement are absent infrastructure, and remain explicit blockers to claiming production/staging SL completion. They do not block local Stage 1 implementation. No provider credentials or legal rule decisions are needed for Stage 1. Real business schedules are not supplied; leave unconfigured workers in “Enter actual times” and allow office configuration. No new dependencies are planned.
